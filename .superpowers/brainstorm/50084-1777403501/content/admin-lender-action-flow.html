Auditable admin action flow

The target lender remains the business subject; admin identity is attached as required metadata.

Read and write paths
Read flow

Admin opens lender record
→ Portfolio tab sends targetLenderId
→ admin query validates FairLend admin
→ resolves lender + single broker context
→ shared portfolio builders return exact contract
Action flow

Admin clicks lender action
→ mutation receives targetLenderId
→ business rules run for target lender
→ event/action records target lender
→ audit metadata records admin actor
Required audit metadata: admin user/auth id, target lender id, action source, timestamp, reason when action is consequential, and original business record ids.
