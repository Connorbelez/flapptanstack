MIC Delivery, Error Handling, And Testing

Clear duplicate-request behavior, fail-closed access rules, and frontend delegation boundaries

Operational Rules
Duplicate public request by same email → return success-style response and reuse/open existing pending request
Rejected email can re-request later only if staff policy allows; default recommendation: allow a fresh request after rejection
Approved-but-provisioning-failed request remains visible as admin exception, not silently lost
MIC portal route fails closed if portal-to-lender mapping is missing or invalid
Access Boundary Rules
Public landing page is always accessible
/portal requires auth + MIC permission + valid MIC portal host
Non-approved users can sign in, but route boundary shows unauthorized / wrong-portal state instead of leaking fund data
Queries validate MIC lender mapping before loading dashboard contracts
