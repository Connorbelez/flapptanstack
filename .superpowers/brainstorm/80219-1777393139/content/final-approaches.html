Final Approach Options

All options preserve document groups as signing-envelope definitions. The difference is how much package governance we add now.

A. Minimal Package Builder
Package = current groups + current documents
No package publish/version lifecycle
Deal lock snapshots final result

Lightweight Composition

Fastest implementation. Useful for early operations, but package standards remain mutable and harder to audit before lock.

B. Published Package Versions
Draft package definition
Publish immutable package version
Lock deal from package version

Versioned Standard Packages

Strong governance for reusable standards. Good audit story, but mortgage-specific overrides and lock snapshots still need careful handling.

C. Versioned Standards + Mortgage Application + Lock Snapshot
Document Engine
Packages: groups + standalone docs + variable matrix
Mortgage Files
Apply/override package standard for future locks
Locked Deal
Immutable package snapshot + generated docs + deal links

Governed Package Pipeline

Recommended. Package standards are versioned, mortgages can apply them with future-only semantics, and each locked deal stores a complete immutable package/envelope/document snapshot.

Recommendation: C

  • Matches the existing mortgage blueprint and deal package lifecycle
  • Keeps groups complementary as envelope definitions
  • Supports multiple Documenso envelopes per deal package
  • Gives operators package-wide variable assurance before publish

Tradeoff

  • Largest implementation surface
  • Requires explicit package definition/version contracts
  • Needs more cross-surface tests
